# راهنمای کامپوننت‌های استاندارد

این سند کامپوننت‌های استاندارد پروژه را مشخص می‌کند تا یکپارچگی در استفاده از کامپوننت‌ها حفظ شود. توسعه‌دهندگان (AI یا انسان) باید **فقط** از کامپوننت‌های لیست‌شده در این سند استفاده کنند. استفاده از کامپوننت‌های غیراستاندارد یا نصب پکیج‌های مشابه ممنوع است.

## ۱. هدف
- اطمینان از استفاده از یک کامپوننت واحد برای هر نوع قابلیت (مثل اسلایدر، مودال، تکست‌اریا).
- جلوگیری از نصب یا ایجاد کامپوننت‌های تکراری یا متفاوت.
- ساده‌سازی نگهداری و توسعه پروژه با یکپارچگی در کدها.

## ۲. لیست کامپوننت‌های استاندارد
هر کامپوننت استاندارد شامل نام، مسیر فایل، و توضیح مختصر است. توسعه‌دهندگان باید از این کامپوننت‌ها استفاده کنند:

| نوع کامپوننت     | نام کامپوننت       | مسیر فایل                                | توضیحات                           |
|-------------------|---------------------|------------------------------------------|-----------------------------------|
| دکمه             | Button             | `components/ui/button.tsx`              | از shadcn/ui، برای دکمه‌های عمومی |
| اینپوت          | Input              | `components/ui/input.tsx`               | از shadcn/ui، برای فیلدهای متنی  |
| تکست‌اریا       | Textarea           | `components/ui/textarea.tsx`            | از shadcn/ui، برای ورودی چندخطی  |
| مودال           | Dialog             | `components/ui/dialog.tsx`              | از shadcn/ui، برای مودال‌ها      |
| اسلایدر         | Slider             | `components/ui/slider.tsx`              | از shadcn/ui، برای اسلایدرها     |
| فرم             | Form               | `components/ui/form.tsx`                | از shadcn/ui، با react-hook-form |
| Toast            | Toast              | `components/ui/toast.tsx`               | از shadcn/ui، **فقط برای پنل‌های ادمین** (مثل `/dashboard/*`, `/admin/*`) |

## ۳. قوانین استفاده
- **استفاده اجباری**: توسعه‌دهندگان (AI یا انسان) باید فقط از کامپوننت‌های لیست‌شده در جدول بالا استفاده کنند.
- **ممنوعیت پکیج‌های جدید**: نصب پکیج‌های جدید برای کامپوننت‌های مشابه (مثل اسلایدر یا مودال دیگر) ممنوع است.
- **محدودیت Toast**: کامپوننت `Toast` فقط در پنل‌های ادمین (مثل مسیرهای `/dashboard/*` یا `/admin/*`) مجاز است. استفاده از `Toast` در سایت یا نرم‌افزار اصلی (مثل صفحات عمومی یا مسیرهای غیرادمین) ممنوع است.
- **ایجاد کامپوننت جدید**: اگر نوع کامپوننت جدیدی نیاز است (مثل یک کاروسل خاص):
  1. کامپوننت را طبق CODING_GUIDELINES.markdown در `components/features/` یا `components/ui/` ایجاد کنید.
  2. کامپوننت را به جدول بالا اضافه کنید.
  3. داکیومنت را در `docs/components/COMPONENT_GUIDELINES.markdown` به‌روزرسانی کنید.
- **تست‌نویسی**: برای هر کامپوننت جدید، تست‌ها را طبق TESTING_GUIDELINES.markdown در `tests/__tests__/` ایجاد کنید.

## ۴. فرآیند به‌روزرسانی
- **اضافه کردن کامپوننت جدید**:
  1. توسعه‌دهنده (AI یا انسان) باید کامپوننت جدید را در جدول بالا اضافه کند.
  2. جزئیات شامل نام، مسیر فایل، و توضیح مختصر را وارد کند.
  3. تغییرات را در `docs/components/COMPONENT_GUIDELINES.markdown` ذخیره کند.
- **بررسی تغییرات**: قبل از merge، تیم توسعه باید تغییرات داکیومنت را بررسی کند تا از رعایت استانداردها مطمئن شود.

## ۵. نکات
- برای سازمان‌دهی فایل‌ها به CODING_GUIDELINES.markdown مراجعه کنید.
- برای تست‌نویسی کامپوننت‌ها به TESTING_GUIDELINES.markdown مراجعه کنید.
- برای مستندسازی تسک‌های مرتبط به TASK_DOCUMENTATION_GUIDELINES.markdown مراجعه کنید.
- برای اقدامات قبل و بعد از تسک به before_task.md و after_task.md مراجعه کنید.
- برای نصب پکیج‌های مجاز به GENERAL_GUIDELINES.markdown مراجعه کنید.
