# راهنمای مستندسازی تسک‌ها

این سند دستورات لازم برای مستندسازی تسک‌ها را مشخص می‌کند تا هر فردی بتواند به‌راحتی به تسک مسلط شود.

## ۱. محل داکیومنت تسک‌ها
- داکیومنت‌های تسک در `docs/tasks/` با نام `[shamsiDate]-[TaskID]-[TaskName].md` (مثل `1404-05-01-T123-UserManagement.md`) ایجاد شوند.
- برای آپدیت تسک‌ها، از نام `[shamsiDate]-[TaskID]-[TaskName]-v[n].md` استفاده کنید (n شماره نسخه آپدیت، مثل v1 برای اولین آپدیت).

## ۲. قالب داکیومنت تسک
- هر داکیومنت تسک شامل بخش‌های زیر باشد:
  - **عنوان تسک**: نام و ID تسک (مثل `T123: پیاده‌سازی مدیریت کاربران`).
  - **تاریخ شمسی تسک**: مثل `1404/05/01`
  - **توضیحات**: شرح مختصر هدف تسک.
  - **ابزارها و کتابخانه‌ها**: لیست ابزارها/کتابخانه‌های استفاده‌شده (مثل React Query، shadcn/ui). برای کامپوننت‌ها، فقط از موارد لیست‌شده در COMPONENT_GUIDELINES.markdown استفاده شود.
  - **قواعد و داکیومنت‌های مرتبط**: ارجاع به داکیومنت‌های مربوطه (مثل API_GUIDELINES.markdown، COMPONENT_GUIDELINES.markdown، API_DOCUMENTATION.markdown).
  - **مراحل انجام**: مراحل دقیق انجام تسک به‌صورت گام‌به‌گام.
  - **نکات تکمیلی**: هرگونه نکته یا هشدار (مثل ملاحظات عملکردی).
- برای داکیومنت آپدیت، بخش اضافی **تغییرات نسبت به نسخه قبلی** اضافه کنید که لینک به داکیومنت اصلی و لیست دقیق تغییرات را شامل شود.
- مثال:
  ```markdown
  # T123: پیاده‌سازی مدیریت کاربران

  ## توضیحات
  افزودن قابلیت‌های CRUD برای مدیریت کاربران در پنل ادمین.

  ## ابزارها و کتابخانه‌ها
  - React Query
  - shadcn/ui (فقط کامپوننت‌های استاندارد از COMPONENT_GUIDELINES.markdown)
  - TypeScript

  ## قواعد و داکیومنت‌های مرتبط
  - API_GUIDELINES.markdown
  - CODING_GUIDELINES.markdown
  - COMPONENT_GUIDELINES.markdown
  - API_DOCUMENTATION.markdown

  ## مراحل انجام
  1. فایل `lib/api/users.ts` را ایجاد کنید.
  2. توابع CRUD را طبق API_GUIDELINES تعریف کنید.
  3. کامپوننت `UserForm.tsx` را در `components/features/` ایجاد کنید.
  4. هوک `useUsers.ts` را در `lib/hooks/` ایجاد کنید.
  5. تست‌ها را در `tests/__tests__/Users.test.tsx` بنویسید.
  6. مستندات API را در `docs/api/endpoints/` اضافه کنید.

  ## نکات تکمیلی
  - از تایپ‌های دقیق در `types/user.ts` استفاده کنید.
  - پوشش تست حداقل 80% باشد.
  ```

## ۳. نکات
- داکیومنت‌ها باید ساده، واضح، و دستوری باشند.
- از تکرار مطالب موجود در داکیومنت‌های دیگر پرهیز کنید و به‌جای آن ارجاع دهید.
- فایل‌ها در `docs/tasks/` با فرمت Markdown ذخیره شوند.
- برای انتخاب کامپوننت‌ها به COMPONENT_GUIDELINES.markdown مراجعه کنید.
- برای مستندسازی APIها به API_DOCUMENTATION.markdown مراجعه کنید.
- برای اقدامات قبل و بعد از تسک به before_task.md و after_task.md مراجعه کنید.
- برای اقدامات قبل و بعد از آپدیت تسک به before_update.md و after_update.md مراجعه کنید.
